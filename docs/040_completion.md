# 完了の判断

Issueで約束した体験を実際に得られたと確認したとき、変更は完了します。

- 入力、結果、対象外が現在のIssueと一致している。
- 関係するシナリオ、ケース、コード、システム説明が変更後の姿になっている。
- 自動検査と中心の利用操作を実行し、結果を観測している。
- PRに結果と未確認事項、要求から変わった点がある。

関係しない文書の変更や「変更なし」の追記は不要です。更新先は[開発の進め方](000_process.md)に従います。

未達は未達、未確認は未確認です。合意なく対象外へ移して完了にしません。変更前後の利用操作を録画し、新しい入口は変更後だけを示します。文書・内部整理など録画できる入口がない場合は理由をPRへ一行書きます。
